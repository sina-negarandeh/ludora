# cf_svd — Matrix Factorization (Truncated SVD)

**Model ID:** `cf_svd` · **Category:** Collaborative Filtering · **Status:** Implemented, served

## Data

- Source: `data/processed/master_ratings.csv` (`scripts/train_svd.py`) or `data/raw/user_ratings.csv` (`scripts/precompute_cf_recommendations.py` — see Known limitations).
- Fields used: `user_id`/`user`, `game_id`/`item`, `rating`.

## Model / Architecture

`sklearn.decomposition.TruncatedSVD` over the item×user sparse ratings matrix (`backend/app/recommenders/collaborative/svd.py`, `SVDRecommender`). Decomposing the *transposed* matrix directly yields item embeddings — no separate user-embedding step is needed since only item-to-item recommendations are served. Recommendations are nearest neighbors (cosine similarity) in the resulting embedding space.

## Hyperparameters

Source of truth: `backend/app/core/ml_config.py::RecommenderConfig` / `RANDOM_SEED`.

| Param | Value |
|---|---|
| `CF_SVD_N_FACTORS` | 50 |
| `RANDOM_SEED` (→ `TruncatedSVD(random_state=...)`) | 42 |

## Training

Real `fit()` step: `TruncatedSVD.fit_transform()` on the item×user matrix.

- Primary script: `scripts/train_svd.py` — trains once, pickles the fitted embeddings to `data/models/cf_svd.pkl`, then `scripts/precompute_svd_recommendations.py` loads that pickle and writes top-20 rows per game to `game_recommendations`.
- Commands:
  ```bash
  uv run --project backend python scripts/train_svd.py
  uv run --project backend python scripts/precompute_svd_recommendations.py
  ```
- MLflow experiment: `recommender/collaborative` (run names `cf_svd_train` and `cf_svd_precompute_from_pickle`) — logs `n_factors`, `random_seed`, `n_ratings`/`n_users`/`n_items`, and the artifact itself. Same experiment as `cf_item_cosine`/`cf_als` so all three are directly comparable as runs.

## Artifact

`data/models/cf_svd.pkl` — the working copy `precompute_svd_recommendations.py` loads at precompute time (gitignored, regenerated by `train_svd.py`; contains `n_factors`, `item_embeddings`, and the item-id↔index maps as a raw pickle). Every `train_svd.py` run also logs this same file to MLflow via `mlflow.log_artifact()`, so past versions remain inspectable (`uv run --project backend mlflow ui --backend-store-uri sqlite:///mlruns/mlflow.db`) even after the local pickle is overwritten by a later run.

## Evaluation

- Script: `backend/evaluation/cf_split.py` — Precision@10 / Recall@10 / NDCG@10, seed 42, 1,000 sampled users.
- MLflow experiment: `recommender/collaborative` (run name `cf_svd_eval_cf_split`).
- Results file: `backend/evaluation/results/cf_split_cf_svd_latest.json`.
- Coverage/ILD diagnostic: `backend/evaluation/results/recommenders_coverage_ild_latest.json`.

## Known limitations

- **Duplicate pipeline**: `scripts/precompute_cf_recommendations.py` *also* fits a fresh `SVDRecommender` in-memory (from a different CSV — `data/raw/user_ratings.csv` rather than `data/processed/master_ratings.csv`) and writes its own top-10 `cf_svd` rows, independently of the pickle-based path above. Both write to the same `model='cf_svd'` rows in `game_recommendations`; whichever script ran most recently wins. This was flagged, not consolidated, in this pass.
- The pickle format is a hand-rolled dict, not a standard sklearn artifact — `mlflow.sklearn.log_model()` isn't used, so MLflow's model-registry flavor tooling (e.g. one-line reload via `mlflow.pyfunc.load_model`) doesn't apply here; loading still requires `SVDRecommender.load()`.
